# 工作台全局状态：资料目录与原生会话

这是社区的设计与开发约定，用于有本地资料和原生 Agent 协作的工作台；不是新增的 Desktop API。宿主能力仍按目标 Desktop 版本核验。没有本地资料或 Agent 功能的项目应说明不适用，不制造假的连接状态。

## 用途与位置

资料目录回答“业务数据保存在哪里、现在是否已就绪”；原生会话回答“当前对话是否确实属于本工作台，并关联当前业务项目”。两者独立：目录可用而没有会话时，检索、编辑和保存仍应可用。

在业务面板顶部展示一组全局状态，跨 Tab 共用。绿点配文字，未就绪配灰色，待恢复配琥珀色，明确目录故障配陶土红。颜色不是唯一线索；不闪烁、不用持续动画吸引注意。状态不覆盖宿主的导航、模式、模型或权限控件。

完整的目录选择/切换统一放在数据配置。项目选择/新建只在需要当前项目的工作流出现；结果页若有独立的项目筛选，可隐藏重复的项目操作栏。隐藏前确认用户仍能辨认记录所属项目。

## 状态合同

| 指示器 | 可见文字示例 | 判定来源与后续动作 |
| --- | --- | --- |
| 资料目录：检查中 | 正在检查资料目录 | 启动、切换目录或恢复后等待后端初始化；不得沿用上个目录绿灯 |
| 资料目录：未选择 | 未连接资料目录 | 尚无用户确认目录；进入配置选择，取消不产生副作用 |
| 资料目录：就绪 | 资料目录已连接 | 后端成功打开确认目录下的业务存储；不是单纯存在一个路径字符串 |
| 资料目录：故障 | 资料目录不可用 | 路径失效、权限/初始化或实际读写失败；具体原因与重新选择入口放配置/错误提示 |
| 会话：检查中 | 正在检查会话 | 当前项目或宿主会话切换后，等待对应的新快照 |
| 会话：无业务项目 | 未选择项目 | 先选项目；不自动建会话 |
| 会话：未创建 | 尚无原生对话 | 业务可用；提供用户主动打开/新建会话的入口 |
| 会话：未匹配 | 当前对话未绑定 | 有对话，但其归属或项目映射不匹配；不能显示绿色 |
| 会话：其他映射 | 项目会话未激活 | 项目已有映射，但当前对话不是它；显式打开对应会话 |
| 会话：已绑定 | 对话已绑定 | 当前前台工作台、宿主当前会话的 owner、当前项目映射及映射保存均确认成功 |
| 会话：不可验证 | 会话状态暂不可用 | 归属 API 异常或缺能力；显示可重试，不当成普通未绑定并反复创建 |
| 独立网页预览 | 原生会话仅在 Desktop 内可用 | 只展示业务；不伪装成已连接 Desktop |

“数据保存成功”“草稿追加成功”“操作失败”是一次动作的反馈，不能代替上述持久状态。移除含糊且长期残留的“操作未完成”；用 Toast 或就近错误文字解释具体原因，不能吞掉失败详情。

## 开发方法

1. 在后端为目录建立检查中/未选择/就绪/故障状态。若使用 `configured`，先约定它表示存储初始化成功，而非仅保存配置；后续实际读写失败使状态失效，按需重新检查，不承诺持续监测磁盘。
2. 在一个宿主适配层订阅当前工作台和当前会话，核验 `isActive`、`currentSession`、`ownsSession` 等当版真实能力。owner 返回 owned/not-owned/unavailable 三态，异常不能冒充“不是我的”。业务项目映射由应用维护，与宿主 owner 分开。
3. 向视图提供经过归一化的快照：当前项目、当前会话、owner、是否前台、映射项目、映射是否成功保存。使用自己的消息字段，不把 `sessionReady` 等社区字段说成宿主原生 API。
4. 切换目录/项目/会话立即进入检查中。每次异步请求带目录与项目身份、递增代次；只接收当前代次的结果。确保新建会话返回后，宿主的当前会话与 owner 已切换，再保存映射并点亮绿灯；超时可重试。
5. 一个状态读模型供所有页面使用。不要分别在每个 Tab 探测或创建会话；localStorage 的上次选择不能证明当前绑定。跨 iframe 校验消息来源窗口与 origin，在宿主层校验工作台/会话/项目边界。
6. 渲染用 `textContent` 或框架文本节点；状态加 `role="status"`，变化时播报。辅助说明写明下一步；公开导出/截图不输出完整本机路径、会话 ID 或用户资料。窄面板换行，大字不遮挡版本、外观或公共入口。

复制参考：[状态派生函数](../examples/workbench-status.mjs)。它只计算展示结果，不探测文件系统、不调用 Desktop、不授予权限、不建立会话。调用者仍须落实真实核验、映射落盘及过期结果丢弃；由 `init` 连同本说明复制进项目，不会自动替项目接通能力。

```js
import { deriveWorkbenchStatus } from './examples/workbench-status.mjs'
const view = deriveWorkbenchStatus({
  directory: { phase: 'ready' }, // 后端已成功初始化资料存储
  selectedProjectId: 'project-a',
  session: {
    context: 'desktop', phase: 'ready', snapshotProjectId: 'project-a',
    active: true, currentSessionId: 'session-a', snapshotSessionId: 'session-a', ownership: 'owned',
    mappedProjectId: 'project-a', mappingSaved: true, hasProjectSession: true,
  },
})
// view.directory / view.session 含 code、tone、label，可映射到任意 UI 框架。
```

UI token 建议：`ok` 绿点、`neutral` 灰点、`pending` 灰点+检查中文字、`warning` 琥珀点、`error` 陶土红点。文字随项目术语变化，判断条件不跟随皮肤变化。

## 最小检查矩阵

| 场景 | 预期与取证 |
| --- | --- |
| 首次启动，无目录/无会话 | 不亮假绿灯；仍可操作适用的非会话业务 |
| 目录选择取消/成功/失效/恢复 | 取消不改原状态；成功后才绿；故障失效并给恢复入口；恢复重新检查 |
| 目录已连接但没有会话 | 目录绿、会话中性，两个状态不互相覆盖 |
| owner 正确但项目映射错误或保存失败 | 会话不得亮绿；错误可理解且可重试 |
| 其他工作台会话或 owner API 异常 | 分别为未匹配/不可验证；不改归属、不反复新建 |
| 快速切换 A→B，A 的检查晚到 | A 结果丢弃；B 不因旧快照显示绿色 |
| 新建/恢复会话存在异步延迟 | 等宿主切换、owner 和映射确认后才绿；草稿保留且不自动发送 |
| 跨 Tab/会话与重启恢复 | 一个共享状态；重启重新核验，不用上次绿灯当证据 |
| 窄面板、大字、键盘/读屏 | 状态可读、不挤主任务、不仅靠颜色、无持续闪烁 |
| Git、安装副本与实际界面 | Git 推送不等于本机安装；版本/hash/profile一致并实际打开才能记加载成功 |

先用状态派生检查覆盖“假绿色”和过期快照，再做本次改动影响到的实机分支。记录实际执行者、版本、结果和未验证项；用户明确确认的手工验收可记录为用户确认，不必重复相同操作，也不能扩张其确认范围。

常见坑：把“有路径”当可读写；把“有一个会话”当当前项目绑定；把“草稿已追加”当映射已持久化；用保存文案覆盖连接状态；跨页重复目录配置；关闭一个错误Toast就把灯改绿。这些都应通过独立状态源和上述矩阵避免。
