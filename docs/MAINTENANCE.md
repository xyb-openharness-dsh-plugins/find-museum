# 维护脚手架与开发记录

一个规则只在一个位置维护：AGENTS 放短约束，指南放理由与例子，模板放填写结构，reference 放来源。每轮故障新增最小记录：影响、根因、修复、验收和适用范围。将稳定经验上提到 AGENTS 前先看是否只是个案。

升级官方规范：获取官网当前文档到新快照，记录日期/URL/hash，与旧快照 diff；更新涉及的注册、目录/会话、安装和自测约定，验证模板后再改来源 manifest。历史快照保留，不能静默覆盖后声称旧项目按新版验过。

更新设计：原型另存/提交，记录 hash；先改功能树/差异矩阵，再写 UI。新页面不用重读所有日志，读 BRIEF、相关 SPEC、TASKS 当前段和对应 LESSON ID。交接示例：

```text
版本/分支：...
已完成：ID ...；证据 ...
当前问题：复现步骤/实际错误 ...
未验证：Desktop 重启后加载/外部服务 ...
下一步：文件/动作/具体命令 ...
用户已确认的偏好和授权：...
```

本脚手架不自动修改 ~/.codex 或宿主技能配置。复制到新工程时项目 AGENTS 与团队既有规则合并；不要覆盖原仓库 AGENTS/锁文件/未提交代码。社区素材和技术经验可替换；保持原始来源和许可证提示。

CLI 通过 Git 分发与本机链接激活。更新命令只更新其克隆；业务项目不自动跟随模板，来源由 .dsh-wb-starter.json 记录。CLI 参数/入口变化先更新 spec/CLI-SPEC.md，验证失败/冲突/同步路径后再发布。
