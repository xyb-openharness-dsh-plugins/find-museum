## 在共创流程中的位置

需求与任务优先级 → 风格决策 → frontend 专用技能制作 UI → 实际预览 → 开发者确认 → 实现与回归。Taste Seed 提供风格选择依据，frontend-design 或 design-taste-frontend 等实际可用技能负责界面设计执行；能力重叠时指定一个主设计者，避免叠加冲突规则。

先通过互动确定用户期待的体验，如安心、清晰或专注。随后按需查看情绪索引与相关代码风格卡，选择一个主要方向；确有需要再加一个辅助方向。将色彩、光影、线条、构图和情绪逐项映射到可执行的 UI 参数。完成后检查实际效果并记录开发者反馈，确认后的参数进入项目 token 与 UI-DESIGN。

## Workbench 参数转译示例（本社区建议）

例如患者记录工作台可讨论“清晰”为主、“温和”为辅；这是待用户确认的候选，不是默认业务方案。

| 风格维度 | 工作台要做的具体决定 | 示例 |
| --- | --- | --- |
| 色彩 | 语义 token、强调与状态色 | 薄荷绿组织内容，橙色突出主要动作；状态另用文字/符号说明 |
| 光影 | 面板分层、阴影与透明度 | 轻阴影分层；正文区域保持足够实底与对比 |
| 线条 | 图标、描边、图表线宽 | 统一图标线宽，折线保持几何比例 |
| 构图 | 栅格、对齐、密度与留白 | 按任务分组，组间距大于组内距 |
| 情绪 | 文案、动效与操作反馈 | 表达支持和可操作下一步；装饰动效可停用 |

阅读、键盘操作、信息完整、宿主边界、原型合同优先于装饰。上游面向广泛视觉创作的配色/造型规则须按工作台语义调整，不机械限制必要的图表系列和状态，也不为艺术效果删除功能或降低可读性。具体参数必须在真实业务容器、大字与减少动效设置下验收。

## 按需使用和便携性

开发环境已部署 taste 时，先读取其实际技能入口，按技能根目录解析 references，只查当前任务有关的索引和卡片，不一次加载整库。未部署时可只读访问上游，或采用本社区指南的替代流程；记录实际阅读的文件、提交与不可用项，不声称技能已经激活。

上游当前要求种子库置于技能内部或无技能机制时的稳定独立目录，避免被 workspace 清理。上游 README 的部分部署示例与较新 TASTE/注入文档存在路径差异，若要安装，应以锁定提交中的目标 Agent 部署文档与实际脚本核对。脚手架不自动改写全局 Agent 规则，不把个人绝对路径变成生成项目的运行依赖。

仓库树核对时未发现独立 LICENSE/COPYING 文件；如需随脚手架分发原文、全库或素材，先明确对应许可。本次仅加入方法适配、引用和项目记录结构，无需安装新依赖。

## 反馈沉淀

将目标感受、主辅方向、转译参数、预览证据和用户接受/拒绝原因填入 templates/UI-DESIGN.md。项目反馈保存在项目内；修改上游个人种子库副本属于独立动作。下次设计先查看已确认偏好，避免每次从默认样式重新试错。
