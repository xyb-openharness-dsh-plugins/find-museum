# 如何维护开发复盘

复盘围绕可以复用的决策、故障与验收证据，不以某个业务项目名称或产品版本串联教程。当前脚手架的提交历史由自身 Git 管理。

| 阶段 | 应记录的内容 | 可复用经验 |
| --- | --- | --- |
| 需求与原型 | 决策、确认范围、原型版本/hash、功能清单 | 设计也需要版本控制；页面与交互逐项追踪 |
| 接入基线 | 宿主/运行环境、最小包、真实加载结果 | 先证明可加载，再扩展业务 |
| 实现与修复 | 实际 diff、失败复现、根因、影响功能 | 完整业务单元验收，避免只按标题判断完成 |
| 数据与外部能力 | 迁移、依赖、来源、重试与降级 | 用最终读写结果证明链路可用 |
| 打包与安装 | 源码、tgz、安装副本、运行版本 | 排除旧包、错误 profile 和缓存干扰 |
| UI 与交付 | 容器截图、实际操作、用户反馈、未验证项 | 视觉质量与业务闭环都需验收 |

设计记录、本地版本与 Git 提交是不同证据。局部反馈只覆盖当次明确测试的范围。将故障整理进 [开发典型错误和修复经验](LESSONS.md)，新增记录使用 templates/INCIDENT.md；稳定规则再上提到 AGENTS。
