# Agent、技能、MCP 和资源闭环

## “给我建议”是一项可回顾的任务

页面角色负责聚焦问题，如营养页关注体重/摄入/缺失信息，不通过角色名获取新权限。使用版本化 prompt 模板，带入当前主体、页面范围、已确认事实的日期/单位/来源、缺失与不确定项、用户问题、预期输出结构。不要只传一句“帮我分析”，也不要抓取整页 DOM 当唯一数据接口。

```json
{
  "taskType": "page-advice", "subjectId": "demo-subject-1",
  "page": "nutrition", "promptVersion": "1.0.0",
  "inputSnapshot": {"facts": [], "missing": ["height"]},
  "expectedOutput": ["事实摘要", "需核实内容", "可执行下一步", "来源"]
}
```

集中封装宿主适配：检查前台工作台与 owner；创建/恢复用户确认工作区中的原生会话；读取当前草稿并通过当前 API 合并而非覆盖；保留引用/附件；由用户发送。切换主体、页签或会话时取消旧异步任务，避免旧输入写进新主体。现有实现的 `setDraft(promptRendered)` 只证明能写入，不证明保留草稿，须单独验收。

检索流程：本地有数据先筛选→记录详情→收藏/问 Agent；Agent 查询输出→用户确认→结果库/时间轴。生成文件与重要对话保存索引、session ref、任务 ID、输入快照和来源；对话引用不等于保存完整聊天内容。没有可用回写 API 时提供手工确认导入，不宣称自动同步完成。

## 技能与 MCP 能 bundle 吗

能随包放合法可分发的只读技能说明、prompt、适配代码和小型数据；放进 assets 不会自动成为宿主已注册技能/MCP。需分别说明运行时（Node/Python/可执行文件）、配置入口、权限、版本和来源许可证。不要把 Python venv、node_modules、用户私有 MCP 配置、有效凭据打包。

优先顺序：小型只读本地能力→固定协议的适配器→需要时启用外部服务。缺能力显示可执行的安装/配置提示，保留本地功能。是否用社区 universal-search 或其它服务按项目实际工具注册名核验，不能只写进 prompt 就认为被调用。

## 离线数据开箱即用

附数据 manifest：来源、来源 URL、版本/更新时间、hash、schema 版本、许可证、记录数、压缩/解压大小与稳定主键。小包可随 assets，较大快照按需下载并校验到临时目录，验证 schema 后原子切换，失败保留旧代。公共数据与私人收藏/笔记分表或分库，更新不覆盖收藏。展示“数据截至日期”，过期不伪装实时。

定期同步应使用固定版本资源与 hash，不在用户开机时对仓库无条件 git pull 并执行脚本。离线更新与查询服务分开测。定时订阅保存关键词/靶点/试验名、频率、时区、下次运行、去重键、任务状态与日报；必须确认宿主调度、关机漏跑策略、重试和授权。只有订阅表单不等于 cron 已运行。

市场分发另受官方 O03 约束：本地能 bundle 不代表市场允许，当前市场包禁止携带数据库且有 8 MiB 上限。大型临床快照以独立、可校验、用户知情的本地初始化/更新资源处理；上架前核对当期规则。

## 文件解析和稳定报告

原件导入→预览→选择解析器→必要的云发送提醒→结果保存→候选核对→事实。CLI 可执行、PATH、token、网络、结果下载分别诊断；“任务已接受”不是解析成功。Windows/macOS 用合成样本验证。API 失败可降级 Flash/本地或手工，但说明降级实际边界与错误原因。

多格式报告使用同一冻结快照和版本化渲染器，可作为本机服务或技能；Agent 负责组织任务与解释，不依赖自由文本碰运气生成正确文件。PDF 以 %PDF- 起始，JPEG 有正确标识，DOCX 是 ZIP/OOXML；HTML 不靠改扩展名伪装 PDF。artifact 记录路径、MIME、hash、模板/快照版本。普通 HTML、PDF 图像版与可搜索文本 PDF 的能力差异应写清。

## Spec 到实际提示词的追踪

每个角色的边界/语气必须进入实际发出的 prompt，而不只出现在角色卡简介。集中纯函数组装，测试消费与构建同一源码；检查最终产物和 prompt 文本，防止注释反例或占位符进入输出。重发设定/切换角色需显式用户动作，不能假定 UI 选中即改变模型 system prompt。行为约束的文本测试不保证模型回复质量，需合成场景真实对话复核。
