# 数据模型支持长期前端调整

## 分离稳定事实与易变布局

实体/关系不是 Tab。业务主体、输入资料、解析候选、已确认事实、计划、Agent 任务/结果、收藏、输出文件分别建模。看板、详情与时间轴读同一个事实源；不复制三份数值到三张页面专属表。

最小关系例子：`subject → document → candidate → confirmed_fact`；`subject → observation(metric_definition)`；`subject → schedule → reminder`；`agent_task → input_snapshot → result → artifact`。结果可引用事实/文档/来源数据版本。会话引用是宿主对象的业务关联，不复制 DSH owner 数据作为自己真相。

## 新增指标不一定改表

用 `metric_definition(code,label,value_type,unit_family,category,validation,version)` 定义目录，`observation(subject_id,metric_code,value_num,value_text,unit_code,occurred_at,source_ref,review_state)` 保存记录。增加常规指标只加定义和映射；增加全新关系、检索索引、约束或不同语义才走递增迁移。结构化核心字段与有限扩展字段并用，不把所有关系塞进 JSON。

小量、弱关系的用户确认短文本可用结构化 JSON，须有上限、原子写入、并发策略与迁移。关系查询、时间序列或记录增长时可选 SQLite。用事务、外键、稳定 ID、revision、索引和 migration ledger；迁移前备份，从真实旧库 fixture 验证升级，不通过删库“兼容”。UI 布局每周改动不应触发 schema 修改。读模型显式版本，兼容期由已安装客户端与迁移策略决定，不照抄固定“两周期”。

## 本地目录示例

```text
用户选择的业务资料根/
  workspace.sqlite
  input/YYYY/MM/<document-id>/original.pdf
  input/YYYY/MM/<document-id>/parsed.md
  output/YYYY/MM/<task-or-snapshot-id>/report.pdf
  manifests/                 # 来源/种子数据与输出登记
  backups/                   # 备份策略另定
```

时间轴/分类由数据库元数据组织，不依赖中文目录名推断业务。存相对路径、mime、大小、hash、创建时间、所属主体与来源 ID；文件读取做根目录边界检查。输入原件、可重算解析和正式输出分开。备份 SQLite 时用 SQLite backup/VACUUM INTO 或一致性快照，不能运行中只拷 db 漏掉 WAL。

## 单一事实与失效快照

普通事实变更后，各页重新读取同一读模型。规则分析、临床匹配、报告属于冻结快照：保留当时输入、规则/模板/数据版本，事实变化后标“需重新分析”，不静默改历史结论。预约完成不自动变成“已发生治疗”医学事实。

演示数据带 `demo_id`/manifest，只清单内精确 ID 可清理；不按主体名称猜测或删除整个资料目录来清理。正式初始化去除 demo，不把已有用户记录当试验数据。

## 接口与错误

接口约定 ID、时间/时区、单位、确认状态、分页和错误码。数据新增后验证首页、趋势、导出读数一致。配置写入采用原子替换并保留未知键；密钥配置写入与业务数据分开，不回显实际内容。输入 CSV 的本地解析不能假装成云 OCR；类型、编码、日期、单位错误可定位重试。

## 分级持久化与记忆混合架构

先写业务的预估记录量/文件大小、查询方式、增长、写入者、离线要求和维护能力，再用代表数据测查询与启动体验。以下是选型等级，不是强制升级路线，不以固定记录数替代测量。

| 等级 | 组合 | 适合的业务 | 主要成本与验证 |
| --- | --- | --- | --- |
| A 轻量 | 结构化 JSON + 原件/输出目录；进程内可重建缓存 | 少量记录、弱关系、单写入者、整份加载可接受 | schemaVersion、串行写入/原子替换、大小上限、备份与损坏恢复 |
| B 关系 | SQLite + 文件目录；JSON 存配置/交换快照 | 时间线、多主体、关联筛选、历史趋势、分页与记录增长 | 索引、事务、迁移、写竞争、分页查询、宿主实际 SQLite 运行能力 |
| C 本地混合 | A 或 B 作为事实源 + 有界摘要/偏好记忆 + 可重建检索索引/缓存 | Agent 需跨会话回顾、资料检索或长任务连续性 | 引用来源、版本/失效、命中质量；仅在需要时引入全文或向量检索 |
| D 服务混合 | A 或 B + 可选外部记忆服务（如经核验的 MemOS 或同类） | 多工作区/跨会话检索确有收益且有运维能力 | 接口/版本/部署与发送范围、连接配置、超时、重试、删除传播、离线降级 |

JSON 本身不自动提供并发协调或高速索引；SQLite 也不自动提供长期记忆。业务数据库无需因启用 Agent 而另建一套重复事实库。先满足可靠持久化和常用查询，再引入能证明有收益的记忆能力。

### 四类数据的职责

- **业务事实**：用户确认的记录，JSON 或 SQLite 是权威来源，通过业务 Repository/API 写入；页面、导出和 Agent 快照共用读模型。
- **文件与产物**：原件、解析结果和报告存目录，事实库保存稳定 ID、相对路径、hash 和来源；不把大文件正文塞进每次对话。
- **记忆**：偏好、任务摘要、检索片段附 subject/workspace、source ID/revision、生成时间、有效期与确认状态。模型摘要不能覆盖业务事实；外部检索内容用于参考，冲突优先回查权威记录。
- **运行缓存**：有界内存 Map、查询结果或派生索引，均可重建；键包含主体与 revision，失效不能影响事实。进程内内存关闭后会丢失，不当作持久记忆。

### 更新、检索和恢复合同

业务事务成功后，再通过可重试任务更新可选索引/记忆；记录源 revision、幂等键和同步状态。检索时核对来源是否仍有效，旧版本先过滤或重建；写入记忆失败不回滚已经保存的业务记录，也不能把旧摘要展示成最新事实。

用户纠正/删除记录时失效相关缓存与记忆，删除传播有可见状态；无法撤回的外部副本如实说明。切换主体与工作区需限定检索范围。记忆服务离线时仍可读取、编辑、导出业务数据，Agent 可改用当前确认快照并说明缺少历史上下文。

所谓“结合智能体记忆”需列出实际可调用的宿主 API、MCP 或服务；不假定 DSH 自带 MemOS、向量库、后台同步或会话全量导出。进入实现前按当前官方文档与目标环境验证。验收至少包含重启恢复、跨页一致、主体隔离、旧摘要失效、服务中断和迁移恢复。
