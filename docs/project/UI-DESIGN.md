## 0.2.6 Desktop 状态与页面上下文

完整用途、开发方法与最小检查矩阵见[工作台全局状态规范](../09-WORKBENCH-STATUS.md)，社区脚手架同步维护同一主题。

通用UI经验已确认：主体任务/结果/关键状态常显，非核心申请说明与低频配置折叠，💡浮层收纳教学；内容保留且可发现，关键错误与必要确认不隐藏。该方法用于不同业务主题，不局限于地图申请流程。外部信息按来源、时效、适用条件与核实状态表达，查询返回成功不能直接显示为事实已核实。

- 顶部全局状态区分展示“资料目录”和“原生会话”两种独立状态。目录连接成功显示绿色点；未配置显示红色/陶土色点。当前原生会话与所选旅行确实关联时才显示绿色“对话已绑定”；旅行有其他会话映射时显示提示态，不能误显示为已绑定。
- 会话状态使用 Desktop `context` 的 `sessionReady`、`tripHasSession` 和 `sessionId`；资料目录状态使用启动配置 `configured`。不得用Toast或最近一次保存结果推断这两项状态。
- “操作未完成”不作为持久状态文案。错误通过Toast呈现具体原因；冲突单独保留可恢复提示。
- 旅行选择与新建只在发现、设计路书、收藏等需要旅行上下文的页面显示。路书浏览与数据配置隐藏这条项目操作栏；资料目录切换统一放在数据配置，避免在页面中重复入口。
