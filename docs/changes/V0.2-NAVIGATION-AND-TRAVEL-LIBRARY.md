# 0.2 版修改需求：发现、设计、收藏与路书档案

状态：已进入0.2实现与验收。基线为0.1.0；2026-10-16作者确认继续开发。以下保留完整需求合同；实际通过与待验证项以0.2验收记录为准。

## 1. 目标与问题

现有5个Tab堆在左边，留白未用于分布；“我的路线/我的馆单/路书与结果”的职责不直观。首页加入清单后缺少下一步入口；导出文件即结果，没有完整的应用内浏览、存档和分享路径。配置说明平铺过长。用户还希望把美食、餐馆、景点和Citywalk地点一起纳入旅行收藏。

目标：保持博物馆深度游为主，辅助地点服务同一份路书；用户沿“发现 → 设计 → 存档与分享”前进，收藏库可随时积累、复用。没有时间安排也能先收藏和建清单。

## 2. 导航与标题合同

| 当前 | 新名称（固定顺序） | 职责 |
| --- | --- | --- |
| 发现博物馆 | 发现博物馆 | 博物馆搜索、筛选、地图、加入本次清单，明确下一步 |
| 我的路线 | 设计路书 | 本次候选清单、排序、Day N、辅助地点、Agent完善、保存路书 |
| 我的馆单 | 我的收藏 | 跨旅行的博物馆/美食/景点/Citywalk地点，含想去和去过 |
| 路书与结果 | 路书档案 | 已保存路书的浏览、继续设计、下载、发送Agent、分享、版本 |
| 数据与配置 | 数据配置 | 连接状态与折叠设置，提供必要说明和问题处理 |

内部discover/route/favorites/results/data标识可保留，避免仅改文案就迁移会话/数据。页面大标题与Tab语义一致；诗意短句仅作辅助，不替代“设计路书”等明确功能名。配置页不重复旅行搜索栏；搜索控件限发现页，其他页保留简洁的当前旅行切换。

### 布局尺寸

- 宽度以**Desktop左侧业务容器**为准，不以整个窗口为准；右侧唯一原生Agent不变。
- 容器≥760px：5列等分，Tab在各列居中，图标18–20px、图文间距8px；每项高度≥48px，左右内边距12px。下划线只指示当前项，不铺满整栏。
- 容器480–759px：改为3+2两行，每行等分；不通过缩小字体或把中文压成单字竖排塞进一行。
- 容器<480px：独立菜单按钮/选择器显示当前页和完整5项；保留可到达的全部入口，不只显示图标。
- 默认正文≥16px，导航15–16px；大字模式随容器重排。数字徽标只在设计路书显示“待编排N”之类明确含义，不把所有数字都叫路线数。
- 菜单键盘可达，选中状态含文字/aria-current；折叠控件含aria-expanded；无整页横向溢出。

以上为建议初始断点，实现时用真实标题和65%容器截图确认，可微调断点，不删入口。

## 3. 主流程与一步可见的行动

```text
发现博物馆 ──加入本次清单──> 已选N处 · 去设计路书
      │                           │
      └──收藏──> 我的收藏 ──加入本次清单──┘
                                  ↓
                         设计路书：排序 + Day N
                             │            │
                     请Agent完善      保存到路书档案
                             │            ↓
                        用户确认结果   立即查看路书
                             └───────> 浏览 / 下载 / 发Agent / 分享
```

### 3.1 发现页

- 保留本地历史名录、真实POI搜索、地图筛选、详情、单选/多选/全选。
- “加入本次清单”与“收藏想去”是两个动作：前者服务当前旅行，后者保存到个人收藏库。界面文案不混用。
- 页面底部业务区内设置轻量操作栏：左侧“本次已选N处”，右侧主按钮“去设计路书 →”。给底部内容留安全间距；不覆盖宿主输入框/侧栏。
- N=0时提示“先选几处感兴趣的馆”，下一步禁用并说明；不要求日期、参观时长或Day N。
- 多选保存后显示“已加入N处”，提供同样的“去设计路书”按钮；不强行跳页，允许继续收集。
- 跨页保持当前旅行和清单；切换Tab不创建新会话，不重复添加同一馆址。
- 无旅行时可先暂存本机当前来源的未归属选择，点击保存/下一步再选择或新建旅行并确认资料目录；取消保留待选状态，不创建空项目。暂存标“尚未保存到旅行”，不能伪称已落盘。

### 3.2 设计路书

- 顶部只显示“当前旅行/已选N处/已编排N处”摘要，不把完整第一步清单、完整路线和重复提示堆在同一视口。
- 主体按Day N分组，提供“调整顺序与天数”弹窗；拖拽排序+上下箭头备选，Day1–30；支持把尚未编排地点加入某天。
- 设计草稿可自动保存，但底部主动作是**“保存到路书档案”**；次动作“请Agent完善”。导出格式收进档案下载菜单，不并排铺4个按钮。
- 博物馆：4小时基本参观，6或8小时深度参观，不支持1–2小时打卡。此规则只作用于museum类型，不能误用于吃饭、散步或其他景点。
- 不要求具体出发时刻。日期可选，仅用于核实营业/预约；Day N是主时间轴。
- 每日展示分类型时长和交通待核实，不用尚未查证的营业时间宣称行程一定可行；时间过密只提示可调整，不阻止收集。
- 保存成功后明确“路书已存档”，主按钮“查看路书”，次按钮“继续设计”；点击查看定位到刚保存的档案，不让用户自己猜哪个Tab。
- 可先保存仅有清单的草稿档案，标“待编排”，也可发Agent建议安排；正式规划标“已编排”，Agent返回内容标“待确认”，用户认可后标“已确认”。没有Agent工具时仍可手工编排和保存。

## 4. 我的收藏：统一旅行地点库

### 4.1 分类与状态是两组独立标签

- 地点类别：全部 / 博物馆 / 美食 / 景点 / Citywalk。
- 参观状态：全部 / 想去 / 去过。评分、城市、主题可作次级筛选，不全部挤在标题行。
- 同一地点可同时有“本地小吃、老字号、街区”等多个主题标签；主类别用于展示和时长规则。去过不是类别，取消“去过”恢复“想去”，不丢备注。
- 首页收藏默认“想去”；用户显式标去过，绝不因到达日期或保存路书自动标去过。
- 卡片展示名称、类别、城市/片区、距离及其中心、来源、评分来源和核实时间（若有）、收藏状态、笔记；主动作“加入本次路书”，次动作“查看详情”。
- 手动添加：名称和类别必填，地址/来源可补，未定位地点允许收藏但不参与地图/距离/道路计算；后续可用高德匹配。
- 收藏删除只移除个人收藏关联；不删除其他旅行的站点、旧路书快照或公共馆址。

### 4.2 标签推荐：点击一次，先看3–5个候选

推荐入口放在我的收藏上方，在设计路书中也可通过“补充沿途地点”打开同一组件。

建议首批标签：**特色小吃、本地餐馆、老字号、周边景点、Citywalk**。用户提出的“大众点评特色本地餐馆”保留为外部核实目标，不用无证据的点评高分标签替代高德结果。

流程：

1. 用户点标签，显示当前城市/推荐中心（当前馆、某Day或城市）及范围；没有中心则先选城市。首次点击即查询，不再让用户填写整套表单。
2. 读取本地缓存，必要时由本机后端调用高德对应类型POI；弹窗显示3–5条合格候选，勾选保存。用户明确触发后才查询，不后台无限预取。
3. 候选支持单选/多选/全选，默认不勾选；每行“查看详情/地图”和来源。主要按钮“保存到我的收藏（N）”，可选复选动作“同时加入当前旅行清单”，默认关闭。
4. 保存后显示新增数和已存在数；相同provider+poiId不重复保存，原有去过状态和笔记不覆盖。重复点击标签可换一批/重试，但不承诺无限不重复结果。
5. 缺评分/地址/特色字段时明确显示未提供；只有2条合格候选就展示2条并说明，不凑数，不凭名称编菜品或“必吃”。

推荐规则建议：城市与距离符合 → 类别/特色匹配 → 路线顺路程度 → 同平台评分（若有）。不把缺评分当零分，不跨平台直接混排，不给出“全城最高分”或“全城前五”的结论。推荐理由只用真实字段，如“距本馆1.2km；高德标注特色菜××”。

范围采用不同业务默认：博物馆保留100km直线半径；馆边美食建议3km、城市餐馆5km、Citywalk地点3km，可更改并显式显示。高德单次周边查询上限以当版接口为准，不能直接把博物馆100km参数传给所有推荐接口。

### 4.3 高德/大众点评/Citywalk能力边界

- 已核对高德官方POI文档：支持关键词、周边、详情检索；餐饮/酒店/景点等POI**可能**返回评分、人均、特色和营业时间，字段不保证每条存在。
- 当前代码只查博物馆types，需要新增后端类别白名单与类型映射；不能只在前端换关键词，仍过滤为博物馆。
- 高德评分展示“高德评分”，保存provider/value/scale/checkedAt，原始评分范围未确认时不擅自换算五星。
- **大众点评评分/榜单/评论不能由高德评分冒充。** 当前未证明有已授权的大众点评接口。首版提供可核实的原始详情链接/用户补充；Agent有实际可用搜索渠道时可补链接与摘要，标来源和日期。拿不到则保留“待核实”，不承诺自动抓点评全文或绕过登录。
- Citywalk首版推荐街区、公园、历史建筑等**地点候选**；多地点步行路线在设计路书或原生Agent中组合并核实步行路段，不能把单个POI称为已核实的完整Citywalk线路。
- 美食/其他地点的建议停留时间独立配置：餐饮可选30/60/90/120分钟，Citywalk地点可选30/60/120/自定义，景点可选1/2/3/4小时或自定义；只是可编辑规划值，**不套用博物馆4小时硬约束**。

官方依据（2026-10-16查阅）：

- https://lbs.amap.com/api/webservice/guide/api/search/
- https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch

## 5. 路书档案：存档不是仅下载文件

### 列表与详情

- 默认显示全部旅行的档案，提供“当前旅行/全部”、城市、状态筛选；明确标出旅行归属，避免被当前旅行隐藏误以为丢失。
- 卡片展示：名称、城市、Day数、地点数、状态、版本、保存时间；“浏览路书”为主动作。技术哈希收进“文件与来源”，不占主要阅读区。
- 详情按Day N展示顺序、地点类别、博物馆重点、美食/景点补充、规划时间、交通、开放待办和来源。只有清单的草稿展示清单与待编排状态。
- 导入的Markdown/纯文本可读预览；HTML在受限sandbox预览，禁止任意脚本与宿主权限。文件缺失说明“文件未找到”，保留索引并提供定位/重新导出，不假装成功。
- 支持“继续设计”：从当前档案快照创建或恢复设计草稿；旧档案不可被后续编辑悄悄改写。重新存档形成新版本，必要时提示“已有相同版本”，避免重复点击造很多相同文件。

### 发送Agent与分享

- “发送到Agent”使用**当前打开档案的冻结快照**，不能误用另一旅行的实时状态。检查前台、归属与草稿，必要时显式建立会话；只追加，不自动发送。
- “分享给旅伴”首版为弹窗：**下载分享版HTML / 复制行程摘要 / 下载Markdown**。有可用系统分享能力时才显示系统分享入口，否则让用户手动发文件；取消/失败有明确反馈。
- 分享版移除本机绝对路径、会话ID、配置和Key、私人备注（默认不包含，可显式选择）；保留城市、DayN、公开地点和来源链接、核实日期。主数据不因分享被清空或改写。
- 不生成指向127.0.0.1、file://或本机API的“旅伴分享链接”；它们在另一台设备不可用。复制摘要也不等于自动发到微信/群聊。
- 旅伴只读查看首版文件。多人实时共同编辑、云托管分享链接、账号权限与评论为后续扩展，不能假装已经同步成功。用户手动发给旅伴的动作不在工作台内自动执行。

## 6. 数据配置：摘要优先，详情折叠

首屏仅保留简洁状态行：地图连接状态、资料目录状态、名录年份/数量和版本；显示“检查连接”和必要的“修改配置”。

折叠组：

1. **高德地图与搜索**：Key状态摘要；展开后输入/更换Key与检查连接。内部“如何申请Key”再次折叠，保留官方控制台/申请指南。
2. **本地资料与保存**：当前目录、切换目录及保留说明。
3. **名录与来源**：历史年份、覆盖与缺失、来源说明；无“全国CSV下载”按钮。
4. **高级与诊断**：版本、连接错误、导出技术信息。哈希/调试字段按需看。

已配置正常时默认全折叠；首次无Key时地图配置展开，申请步骤仍按需展开；检测失败展开相关错误和处理入口，不自动展开所有说明。不在前端回显Key。

**移除全国历史名录CSV下载：**删除产品入口和专用下载接口，移除功能清单中的该功能。包内CSV继续用于离线索引和可复现开发。无当前业务理由保留入口，不因“文件已经存在”继续放在配置页。此项与路书自身的CSV导出无关，后者仍可在档案下载菜单使用。

## 7. 数据结构与迁移建议（设计，不是已建表）

保留清单与计划分离；不要把美食硬塞进museum表，也不要把已有博物馆ID改名导致旧档案失联。

| 主体 | 设计变更 |
| --- | --- |
| Place | 统一旅行地点索引：id、kind(museum/food/attraction/citywalk)、provider/providerPoiId、名称、城市/adcode、坐标/坐标系/定位状态、来源、检索时间、特色、营业信息；museum链接原museumId/venueId |
| PlaceRating | placeId、provider、value、scale、checkedAt、sourceUrl，可空；不同来源分别存 |
| Favorite | 引用placeId、wish/visited、主题标签、笔记、收藏/参观时间；从现有visited布尔兼容迁移 |
| Selection | 当前旅行placeId清单，不含day/minutes；允许暂存未归属候选，并明确未保存 |
| TripStop | 引用placeId、day、position、minutes；按类别校验时长，博物馆4–8小时规则保持 |
| RecommendationBatch | 查询标签、城市/中心/范围、候选ID、来源与检索时间/缓存有效期；和用户已收藏事实分开 |
| Roadbook | id、tripId、title、status、版本索引、更新时间 |
| RoadbookVersion | roadbookId、version、inputRevision、snapshot、content/文件索引、hash、savedAt；冻结并可浏览 |
| Artifact | 路书版本的导出附件，不再让每个格式文件看起来是一份完全不同路书 |

迁移顺序建议：先引入通用Place并回填既有馆址 → 迁移收藏和选择引用（保留ID兼容） → 重建TripStop约束以支持分类时长 → 归组已有artifact为可浏览档案/旧附件 → 加推荐缓存索引。每一步事务、账本和旧库回归。迁移失败回滚，备份保留；不清库解决UI改版。

## 8. 实施顺序与验收

| 任务 | 范围 | 必须验收 |
| --- | --- | --- |
| R01 | 导航分布、统一标题、删全国CSV下载 | 5入口与新名称；65%容器/大字/键盘可用；CSV接口移除 |
| R02 | 首页下一步、设计页精简、配置折叠 | 加清单无时间；一次点击到设计；状态正常/缺Key/失败折叠行为 |
| R03 | Place/收藏/分类时长迁移 | 旧馆、笔记、去过、清单、DayN顺序保留；餐饮短时不被museum规则拒绝 |
| R04 | 标签推荐与勾选保存 | 3–5候选或真实不足；去重、来源、评分缺失、配额失败、取消不写入 |
| R05 | 档案保存与可读预览 | 草稿/已编排/Agent待确认；版本冻结；全部旅行可回顾；保存后直达详情 |
| R06 | 下载/Agent/旅伴分享 | 真实格式；发送用档案快照；无错误会话；分享无本机Key/路径；非本机链接 |
| R07 | 完整回归与0.2预发布 | 发现→收藏/清单→编排→Agent→确认→存档→预览→下载/分享；安装副本版本/hash和真实Desktop |
